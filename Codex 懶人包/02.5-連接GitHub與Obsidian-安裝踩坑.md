## 實測踩坑

### 1. GitHub CLI 已登入，但 Codex 讀不到設定

錯誤訊息：

```text
failed to read configuration: open C:\Users\User\AppData\Roaming\GitHub CLI\config.yml: Access is denied.
```

判斷：GitHub CLI 本身可用，但 Codex 權限讀不到 GitHub CLI 設定。

處理：允許 Codex 讀取 GitHub CLI 設定後重跑 `gh auth status`。這不一定代表 GitHub CLI 尚未登入。

### 2. npm 全域安裝 mcpvault 時出現 EPERM

錯誤訊息：

```text
EPERM: operation not permitted, mkdir 'C:\Users\User\AppData\Roaming\npm'
```

判斷：Codex 權限不足，無法寫入 npm 全域資料夾。

處理：允許較高權限重跑：

```powershell
npm.cmd install -g @bitbonsai/mcpvault
```

### 3. `where.exe mcpvault` 找不到，不代表安裝失敗

安裝後 `where.exe mcpvault` 可能找不到，因為 PATH 尚未刷新。

改用：

```powershell
npm.cmd prefix -g
Test-Path "$env:APPDATA\npm\mcpvault.cmd"
```

確認命令實際存在即可。

### 4. Google Drive vault 搜尋可能遇到 Access denied

掃描 `G:\我的雲端硬碟` 或 `G:\My Drive` 時可能出現 `Access is denied`。

可改讀 Obsidian 設定：

```powershell
Get-Content "$env:APPDATA\obsidian\obsidian.json" -Raw
```

在 Codex 內讀這個檔案可能也需要額外權限。拿到 open vault 後，再確認 vault 與 `.obsidian`：

```powershell
$vault = "G:\我的雲端硬碟\Second Brain"
Test-Path -LiteralPath $vault
Test-Path -LiteralPath (Join-Path $vault ".obsidian")
```

### 5. PowerShell 管線傳中文 JSON 給 mcpvault 可能變問號

手動用 PowerShell JSON 呼叫 mcpvault 寫入中文 note path 時，中文可能變成 `??`，導致 `ENOENT`。

排查方式：先用 ASCII 路徑測試：

```text
Codex Test/GitHub-Obsidian-Connection-Test.md
```

如果 ASCII 路徑可寫入、可讀回，代表 mcpvault 與 vault 權限正常；問題偏向 PowerShell 管線編碼。

### 6. 更新 `config.toml` 後必須完整重啟 Codex

即使 mcpvault 直接測試成功，Codex 內的 Obsidian MCP 工具不會立刻出現。需要完整關閉 Codex Desktop app 後重新開啟。

## 下次安裝建議順序

1. 先確認 `gh auth status`。
2. 建立測試 repo，驗證 commit/push。
3. 確認 `node --version` 與 `npm.cmd --version`。
4. 安裝 `@bitbonsai/mcpvault`。
5. 用 `npm.cmd prefix -g` 和 `Test-Path` 找到 `mcpvault.cmd`。
6. 從 Obsidian `obsidian.json` 確認目前 open vault。
7. 確認 vault path 與 `.obsidian` 存在。
8. 寫入 Codex `config.toml`。
9. 先用 `tools/list` 測 mcpvault。
10. 用 ASCII note path 測試寫入與讀回。
11. 完整重啟 Codex Desktop app。
