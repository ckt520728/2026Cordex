# End-of-Day Shutdown

Create `briefs/YYYY-MM-DD-eod.md` when the user requests an end-of-day review.

## Evidence review

1. Read today's confirmed brief, `state/tasks.md`, and current source checkpoints.
2. Accept task outcomes from an explicit user statement or authoritative external evidence only.
3. A read email, lack of a reminder, elapsed time, or omission from the user's message is not completion evidence.
4. If an external confirmation is checked, keep the source read-only and record the result without copying unnecessary private content.

## Shutdown output

Record:

- Evidence-backed transitions made today, or `None`.
- Each unresolved committed task and its next concrete decision/action.
- Candidates still awaiting confirmation.
- Opportunities with approaching decision dates.
- Working-memory cleanup: information deliberately moved to Opportunity Inbox or Research Radar rather than tomorrow's active set.
- System friction or deviations worth improving.
- Tomorrow's provisional first action, clearly labeled provisional until the next check-in.

Update `state/pilot-log.md` with review minutes and helpfulness only when the user reports them. Leave fields `unreported` otherwise.

Do not force a positive productivity judgment. A sound day may still have incomplete work; close the loop by preserving evidence and reducing tomorrow's reorientation cost.
